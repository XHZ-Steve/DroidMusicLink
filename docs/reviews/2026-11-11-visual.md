# Independent visual review — runtime images

Reviewer: integration agent, separate context using the inherited model; no
claim of a Luna-specific review. Images are genuine app captures, not mockups.

Reviewed Windows home at 1120 logical width, devices at 800 and settings at
1440 (`artifacts/screenshots/`), plus Android API 30 home/device screenshots
(`android/screenshots/`). Runtime capture includes host scaling, so pixel sizes
can exceed the logical dimensions in filenames.

- Initial Windows Chinese typography fell back to a serif font while English
  used Segoe. Fixed by explicit Microsoft YaHei UI and rechecked in new captures.
- Initial inactive lyric status had too little contrast. Updated status is
  readable; transport disabled styling remains visually distinguishable.
- Lucide replacement gives music/transport controls consistent outlined strokes.
  Main canvas has no fixed sidebar or redundant marketing text, and no overlap
  was observed at the captured sizes.
- Device form has clear address, fingerprint and code labels; the fingerprint
  safety instruction carries a meaningful security purpose.
- Settings gained a category selector and language control. The captured very
  wide layout still leaves substantial empty space; full search/navigation and
  grouped-reset UX is not established by this screenshot.
- Android Material controls, light palette and bottom navigation are consistent.
  Initial no-session label wrapped with a lone final character; reported to the
  Android agent for a shorter empty-state label.
- The 660×620 logical Windows window exposed a connection-button/dock overlap.
  The root agent constrained cover size by available height; the final small
  screenshot was rebuilt and independently rechecked: the connection button now
  has a clear gap above the transport dock, with no overlap.
- Custom tray, floating player and desktop-lyric captures share the same palette,
  font and icon stroke. No clipping was seen in their empty states; screenshots
  do not prove edge-of-monitor placement or click-through behavior.

These captures are offline/empty states. They do **not** verify real artwork,
dark/light extremes, live lyrics, glass/background integration, connected-PC
states, tray popup placement, keyboard focus, high contrast, large fonts or
multi-monitor/DPI behavior. Full visual acceptance remains incomplete.
