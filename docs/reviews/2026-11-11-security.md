# Independent incremental review

Reviewer: integration agent in a separate context, current inherited model.
This is not a claimed Luna review. Scope: Windows Bridge, Android passive server,
PairingStore, MediaMonitor, native SMTC ABI, protocol interoperability.

| Severity | Evidence | Disposition |
|---|---|---|
| P1 | Android volume parsed an integer absolute value while Windows sent 0..1 | Fixed: finite normalized range checked and converted to MediaSession maximum |
| P1 | Revoking stored identity left authenticated sockets receiving metadata | Fixed by Android agent: revoke callback closes matching connections |
| P1 | Main-handler queued controls checked authorization only before queuing | Fixed: second authorization check at execution |
| P1 | Artwork decoded before validating decoded pixel dimensions | Fixed by Windows agent: QImageReader validates size before read |
| P2 | Command replay prevention tracked only messageId, not requestId | Fixed: requestId deduplication added |
| P2 | SMTC init negative HRESULT was treated as true | Fixed: success tested against exact return 1 |
| P2 | DNS-SD used a string match and sender's address with fixed port | Improved: compressed name/SRV/A parsing implemented; IPv6, TTL expiry, comprehensive malformed-record tests remain absent |
| P2 | Android pairing file corruption stopped service | Fails closed; explicit recovery UX remains limited; no silent credential erasure |
| P2 | Windows settings imports accepted unknown key types/values | Fixed whitelist/type/range validation; full descriptor registry/migration remains a gap |
| P1 | Real Android TLS handshake failed with Keystore incompatible RSA padding | Fixed Android TLS key padding/digest authorizations; actual TLS handshake passed |
| P2 | Lyrics/update replies could buffer a full oversized response before bounded read | Fixed download-progress cancellation; per-response limits added |
| P2 | DNS cache accepted unbounded distinct host/service names | Fixed 512-record cap; TTL/IPv6 remain limited |
| P2 | Runtime/native and full real-device behavior unverified | Compilation alone is not acceptance evidence; track in testing.md |

TLS inspection found exact SHA-256 certificate matching before credential send.
Only selected chain/hostname errors for the pinned certificate are ignored;
there is no blanket `ignoreSslErrors()` path. Credentials are encrypted with
DPAPI/AES-GCM and exported preferences exclude their storage namespace. The
phone is the passive listener and enforces a short pairing window, local approval,
connection cap and message rate/size limits. These checks do not replace a
third-party security audit or full hostile-client integration tests.
