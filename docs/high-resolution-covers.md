# 高清封面（1.1.0 preview）

## 使用

设置 → 媒体 → 播放器选择中提供“封面画质”：关闭（默认）、自动增强、优先高清。自动模式在手机原图达到目标分辨率时跳过联网；优先高清始终尝试来源，但不会用更低分辨率图片替换原图。“仅使用手机原始封面”优先于联网模式。目标可选 500、1200、2048px；无法获得足够大的原图时不放大冒充高清。

联网来源现包括网易云（实验性）、QQ 音乐（实验性）和 MusicBrainz / Cover Art Archive。默认顺序为网易云 → QQ → CAA，使用与歌词相同的拖动列表排序、键盘上下调整及分别启停；旧版的单一 MusicBrainz 设置迁移为 CAA 优先。来源无结果、图片损坏或尺寸不优于手机图时，自动尝试下一项。可手动重新获取。设置 → 高级 → 缓存与数据可限制封面缓存（32–2048MB）并清理。清理后立即回到手机封面，不直接发起下载；后续媒体事件仍按当前模式处理，也可手动刷新或切歌。

## 手机与传输

Android 比较 ART_URI、ALBUM_ART_URI、DISPLAY_ICON_URI 中可读取的本地 content/android.resource 图片与发布的 Bitmap，优先更大的有效候选。2048px 内、2MiB 内的有效本地 URI 图片保持原始编码；Bitmap 不放大，至多缩至 2048px，以 JPEG 92 编码，超过 1.5MiB 时单次降至 85。超大图片有解码上限。读取/编码在 IO 协程中按元数据事件执行，保持已有有界失败重试；不添加周期性任务。

手机不再自行下载 HTTPS 封面。播放器公开的 HTTPS artworkUri 会转交 Windows：在电脑异步获取原始图片，补齐无 Bitmap 的情况，也可尝试更大的原始 URI；这属于手机原始封面的读取，不会向 MusicBrainz 搜索元数据。限定常用音乐图片 CDN、CAA/Archive 的 HTTPS 域，校验重定向、大小及超时，不拼接私有接口；未列入的自建/局域网地址不会访问，仍使用 Bitmap/本地 URI 或可选增强。原始 URI 失败仅有三次有界重试，不添加 Android 网络请求。未变封面不随播放状态重复传输；新连接与曲目变化会发送完整封面。协议 artwork 的 Base64 上限更新为 2796204 字符，链路仍有 4MiB 帧上限。

Windows 不再把手机封面统一转成 1024px JPEG，保留收到的有效字节和尺寸。原始 URI 的图片下载限 2MiB；尺寸过大时在电脑工作线程有界缩至 2048px。原始手机图只保留一个当前文件，不会随着重启累积历史文件。手机图片与增强图片有独立身份，重复媒体快照不会把高清图降回缩略图。

## Windows 来源与缓存

CoverArtProvider 定义独立来源接口；MusicBrainzCoverArtProvider 实现查询、限速和 CAA 获取。CoverArtService 管理工作线程解码、缓存、取消与容量约束；不与歌词网络任务共用取消状态。

匹配必须有歌曲名、艺术家、专辑与时长。名称及艺术家规范化后须一致，时长容差 2.5–5 秒；Live、Remix、Acoustic、Instrumental、Remaster、Single/Album 等版本标记需一致，拒绝不相符的合集及歧义专辑组。利用唯一可信专辑组的 CAA canonical front 获取封面，而非任意同名歌曲的图片。此策略偏保守，可能漏配，尤其是播放器缺少专辑、协作歌手格式差异或别名时。

歌曲缓存包含元数据身份与目标分辨率；新歌曲仍验证名称、歌手、时长及版本，再按可信 MusicBrainz 专辑组标识复用图片；不靠艺术家/专辑同名直接复用，避免绕过版本校验。图片保存为 PNG，避免再次有损压缩；映射 30 天过期，失败短暂退避，可手动刷新。缓存按文件修改时间淘汰。后台下载限制 10MiB，解码限制 8192 边长/16M 像素；不会为目标清晰度突破资源上限。

手机原始图也独立生成 ≤512px JPEG 给 SMTC，保留主窗口的原始编码，避免 WebP 等格式依赖系统额外解码器。

主窗口高清 PNG 与 SMTC 缩略图分离：工作线程生成 512px JPEG 给系统媒体桥接，避免突破原生桥接 2MiB 的安全限制；主窗口不因此缩小。两者一起计入缓存预算。

手机图立即显示，下载和有界解码在异步任务完成后才发布有效路径，复用现有双纹理交叉淡入淡出。增强时保留手机图的环境色，避免背景突然跳色；完全没有手机图时，使用工作线程从高清图生成的环境色板。切歌、模式变化和清理缓存使旧回调失效；拖动期间暂存高清结果，结束后再发布。任何失败都不会清空已有手机图。

## 接口规则与图片条款

- [MusicBrainz API 限速](https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting)：请求间隔至少 1100ms，携带应用版本及项目联系地址作为 User-Agent；429/503 尊重 Retry-After，并有失败退避。
- [CAA API](https://musicbrainz.org/doc/Cover_Art_Archive/API)：经 coverartarchive.org 的 release-group/front 入口，使用官方缩略图或原图；仅接受 HTTPS，跳转限定在 MusicBrainz、CAA 与 archive.org 域。图片与 JSON 都有尺寸、时限和重定向检查。
- [MusicBrainz 数据许可](https://musicbrainz.org/doc/About/Data_License)明确不涵盖封面图片。图片版权仍属于原权利人，接口公开不等于图片获得开源或再分发授权。
- [版权与移除规则](https://musicbrainz.org/doc/Copyright_and_DMCA_Compliance)：CAA 图片问题由 Internet Archive 处理。本实现只在用户启用后用于本机当前媒体显示与可清理缓存，不把下载图片打包进软件或源码。
- 启用联网增强会向已启用的来源发送歌曲名、艺术家和专辑；默认关闭，可仅用手机图。

- Bridge 回归验证 1600×1600 手机原图不会缩成 1024px，增强后重复手机快照不降级，关闭后恢复原图。
- 实际 CAA 下载成功：Coldplay《A Rush of Blood to the Head》canonical front，1200×1200、169767 字节。把同一真实图缩至 512px 再放大回原尺寸的 RGB MSE 为 120.975；直接使用源分辨率的额外重采样 MSE 为 0。该数字度量人为降采样引入的误差，不是“AI 清晰度”或真实手机输出测量。
- 在受控 HTTP/解码缓存路径中，真实图片冷处理约 80–125ms（含独立 SMTC 缩略图生成），测试进程工作集约 32.5MiB、峰值约 41.9MiB；这不代表完整窗口/GPU 占用，完整窗口运行另有截图与资源记录。
- 实际 MusicBrainz 搜索返回 HTTP 503，已验证不替换现有封面；完整联网自动匹配的正向实测仍受来源服务可用性限制，没有绕过官方服务。CAA 正向下载不等于自动匹配已成功。
- Android 单元测试、lint、assembleDebug 通过；当前 ADB 无设备，未声称已测真实手机清晰度、能耗或所有播放器 URI 行为。


完整窗口的隔离预览运行（同一真实 CAA 图像，模拟 512px 基线与 1200px 源尺寸，不冒充真机自动增强）：两个窗口均正常退出且无 QML 错误。约 7 秒冷启动/渲染期间，采样峰值工作集分别为 261.3MiB 与 279.2MiB（增加约 17.9MiB），进程 CPU 总时间分别为 2.17s 与 2.44s。该数值包含 Qt/材质/字体初始化和截图，不是稳态 CPU 或 GPU 显存；设置窗口也正常运行，采样峰值工作集 263.5MiB。截图在 artifacts/hd-baseline.png、hd-high.png、hd-settings.png，原始资源记录在 artifacts/hd-window-resource-results.json。

原生 Windows SMTC Artwork Tests 实际执行并返回 0：STA/Unicode/正斜杠路径、同路径换图、内存快照抗文件覆盖、无 revision 的兼容更新、缺失文件失败、同 revision 重试及清理系统封面均通过。Bridge 新增回归同时确认传给原生桥接的是独立 JPEG 的 Windows 本地路径；解码器用例确认该图为 512px 且低于 2MiB。原始日志：artifacts/hd-cover-native-smtc-tests.log。

显式 --test-profile 诊断运行的图片和歌词缓存也保存在该测试目录中，不共用正式配置的缓存目录；正常启动的缓存位置保持不变。

迟到的手机原图若比已经显示的增强图更大，会优先采用手机原图；拖动结束发布暂存高清图时会再次比较尺寸，避免旧结果覆盖刚到达的更清晰原图。相应用例也纳入媒体引擎回归。

Android 会比较三种 Bitmap 候选的有效输出尺寸，而非固定采用第一个字段。后续元数据发布更清晰 Bitmap 时，在保留现有图片的同时尝试升级；相同尺寸不重复编码，失败后有事件驱动的短暂退避。编码结果及尺寸只在当前曲目校验通过后一起提交，避免过期 IO 任务污染新曲目状态。

手机原始 HTTPS URI 的 Windows 适配器另有本地 HTTP 回归：验证原始字节保留、禁止 HTTP/本地地址/陌生域及用户信息 URL、取消过期回调；切换媒体会话会重置原始图片来源归属，旧会话的大图不会阻止新会话的有效图片。


## 多来源扩展（1.1.0 preview2）

- 网易云：复用现有歌词适配所使用的匿名 `/api/search/get/web` 搜索；按标题、完整艺术家集合、专辑和时长验证歌曲，随后通过 `/api/song/detail/` 再次校验元数据与专辑标识，只使用返回的 `album.picUrl` 原始图片 URL。不生成图片加密地址，不获取音乐音频、不登录、不访问账号或绕过付费权限。没有截断成 300/500px 的图片参数，也不把低分辨率封面插值冒充高清。
- QQ 音乐：复用已有匿名 `client_search_cp` 搜索并验证相同字段，使用返回的 `albummid` 对应公开专辑图片路径，当前请求 800px。未知 ID、不同专辑或版本冲突不会自动替换。
- 新增适配均为实验性，接口没有面向本项目的稳定性或封面版权授权承诺。公开可读不等于获得再分发许可，图片仅供当前媒体的本机显示与有界可清理缓存；下载图片不进入仓库与安装包。原有[网易云服务条款入口](https://st.music.163.com/official-terms/service)及[QQ 服务协议入口](https://y.qq.com/portal/protocol.html)在此次文档抓取中不可达，不能声称已取得开放许可。用户可关闭任一来源。
- 不增加第三方运行时或复制他人客户端实现。Android 不变，所有搜索、下载和解码在 Windows 端完成。仅请求合法来源允许公开访问的元数据与图片，遇到认证、限流、403 或证书错误时回退，不规避限制。
- Apple iTunes 的[公开条款](https://performance-partners.apple.com/search-api)限定封面促销使用场景，不适合作为本应用的通用缓存图库，因此未集成。Deezer 的[开发者条款](https://cdns-content.dzcdn.net/pdf/CGV-ww.pdf)包含应用上线审批要求，未在没有相应许可时启用。测试的酷狗匿名专辑入口存在 TLS 主机名不匹配，不降低证书校验来接入。
- 缓存键包含启用的来源顺序，图片按 `netease:albumId`、`qq:albumMid` 或可信 MusicBrainz 专辑组标识分隔。更换来源或禁用来源不会误命中另一来源的歌曲映射；新歌仍须通过元数据验证后才复用专辑图片。无专辑元数据的网易云/QQ 查询仅接受唯一匹配的专辑标识；多版本歧义回退。Live、Remix 等仍须匹配，艺术家集合允许顺序及连接符不同，不接受仅包含一位歌手的模糊匹配。

此次真实网络测试使用前一轮手机上播放的《L.I.F.E.》/ Remady、Manu-L / 179505ms：网易云匹配 `439037024`（专辑 `34970029`），原始图片 1400×1400、324037 字节；QQ 匹配专辑 `000YptEz3GQ2Xc`，图片 800×800、218622 字节。实际 C++ CoverArtService 的两来源搜索、下载、解码及缓存重放均通过（`artifacts/multi-cover-live.log`），并非只用脚本下载图片。手机在本轮不在场，尚未测试新安装包与手机实时同步。

新增受控回归覆盖：艺术家顺序、Live/时长/专辑/歌手不符、专辑歧义、来源顺序与停用、跨来源缓存隔离、缓存不发请求、网易云空结果和损坏图片自动回退 QQ、禁止非 HTTPS/陌生域/URL 用户信息。并保留原有六组 Windows 回归。

最终 Windows 构建及 6/6 CTest 通过（24.44 秒），协议 8 个正向/13 个拒绝用例通过，77 个 Android 资源键与 515 条 Qt 翻译检查通过。窗口隔离回放采用上一轮手机的实际元数据及 363×363 封面，真实联网后日志确认网易云自动替换为 1400×1400，窗口正常截图并以 0 退出，无 QML 错误；截图 `artifacts/multi-cover-runtime.png`、日志 `artifacts/multi-cover-runtime.log`。此项是已留存媒体数据回放，不是手机离线时冒充实时连接。


## 切歌调度与来源测试（1.1.0 preview3，2026-11-14）

设置 → 媒体 → 播放器选择中，来源优先级改为与歌词共用的来源列表：拖动手柄排序，也支持键盘上下键；行内提供启停和“测试”。不再枚举六种排列的下拉菜单。原有逗号分隔配置与旧版 MusicBrainz 设置兼容，导入、搜索、分组重置继续有效。

“测试”对当前歌曲执行指定来源的真实元数据查询、下载及解码，显示阶段、尺寸、耗时与错误提示。自动增强关闭时仍可主动测试；测试独立于自动获取，使用自动清理的临时缓存，不替换当前图片。缺少歌曲名、歌手或有效时长时显示等待歌曲信息。不同来源可出现未匹配、网络错误、限流、超时或尺寸不优于手机图等不同状态。切歌取消旧测试、旧下载与旧回调。

本次修复的可复现等待问题：
- 来源遇到 429/503 后，之前的下一首请求会在冷却计时器中等待 60 秒甚至更长，阻塞后续来源。现在仍遵守冷却，但立即跳过该来源；普通的 1100ms 请求间隔保持。
- 顺序获取过去只有单次 HTTP 时限，多个请求及冷却叠加会让用户长时间看不到结果。现在每个来源有 12 秒总预算，超时后取消并转下一项，不影响手机图。
- 请求键以前没有包含手机图尺寸，异步到达的原图会让尚未完成的请求使用旧尺寸阈值。现在尺寸变化会生成新请求，旧回调不能覆盖新状态，失败缓存也按尺寸阈值分隔。
- 不完整媒体信息不再锁定请求键；信息补齐后可自动查询。仅对网络错误、限流及超时进行最多两次额外重试，间隔 8 秒；切歌、关闭增强或手动刷新会取消旧计时器。真实无匹配不会反复联网。

验证：最终构建和 6/6 CTest 通过（37.92 秒），包括 60 秒限流冷却快速跳过、无响应来源限时回退、分批媒体信息/封面尺寸更新、测试与自动状态隔离、QML 实际鼠标拖动持久化顺序、测试及开关交互。协议正反用例通过，529 条 Qt 翻译资源检查通过。

窗口实际运行来源测试：留存的《L.I.F.E.》元数据，网易云封面 1400×1400，533ms；测试后当前显示仍为手机 363×363，符合不替换规则。截图 `artifacts/cover-diagnostics-settings.png`，日志 `artifacts/cover-diagnostics-runtime.log`。使用 `--test-profile ... --cover-provider-test netease` 可复跑同一测试通路。此次 ADB 没有设备，尚未在手机实时切歌时复核，未承诺所有歌曲都能匹配高清图。
