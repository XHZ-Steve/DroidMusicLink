# Windows 歌词与界面优化

## 本轮实现

- 主页提供封面点击切换的三种持久化布局；设置采用六个主分类、页内折叠分组、全局搜索和按需帮助。
- 主画布左右安全边距为 28–64 逻辑像素；设置正文最大宽度 700，另留内侧边距和滚动条空间。窄窗歌词居中，字号随布局适配。
- 布局过渡使用一个 460ms 时钟。先完成 Qt Layout polish，再冻结起止几何；封面和标题同步启动，轨迹避让，快速连续点击从当前显示位置重定向。窗口尺寸、曲目身份变化及隐藏会作废待执行的旧过渡。
- 标题测量与动画几何分离，避免隐式高度、动画宽度和布局目标互相反馈。歌词测量完成后重新定位当前行，渐隐范围在小窗口中不会重叠覆盖整个歌词区。
- 原生 Qt 歌词视图共用媒体时钟，支持逐字、逐行、翻译、罗马音、滚轮/拖动/恢复跟随及独立主窗口/桌面样式和预设。
- 在线 Provider 支持独立启用、排序、测试与优先级回退。手动映射和缓存优先，异步查询按歌曲代际隔离；解码解析移到 Qt Concurrent 工作任务。
- 音量改为竖向悬浮控件；Dock 歌词按钮控制桌面歌词，主播放组保持居中。

## 排查到的问题

1. 相同动画时长不代表相同启动时机。独立 Behavior 与动态 Layout 目标叠加，会产生错拍和终点重定向。
2. 两个 `Qt.callLater` 也不能保证 Layout 已 polish；采样旧槽位坐标会令标题向错误方向移动。现在显式 `ensurePolished()` 后统一采样。
3. 动画宽度参与标题隐式高度计算可形成绑定环；现在由独立目标宽度测量标题。
4. 桌面歌词委托销毁期间仍计算逐字进度，出现空对象访问；已加生命周期保护。另修复最终属性名冲突和测试资源中的 Shader 路径。未取得原始 native crash dump，不能将历史全部崩溃归因于这一处。
5. ListView 默认 currentIndex 会干扰手动滚动；已交给独立歌词聚焦逻辑处理。

## 验证和复现

构建后执行 `ctest --test-dir artifacts/windows-build --output-on-failure`。
其中 QML 测试涵盖设置真实点击、来源拖拽、预设保存/重命名/删除、字重变化不改断行、歌词定位、三种布局、整个运动过程的同步与避让、快速打断、长标题和窗口变化。

仅隔离配置可用的诊断参数：

```
--test-profile <directory>
--preview-media <bounded JSON file>
--preview-cover <image>
--preview-lyrics <local lyric file>
--test-layout <0|1|2>
--category <0..5> --settings-section <index>
--layout-motion-audit <output directory> [--motion-metrics-only]
--resize-audit <output directory>
```

截图采样包含 GPU 读回和文件写入，不能用它测量普通播放的帧率。应使用 `--motion-metrics-only` 记录不截图的动画时间。

## 已知边界

- 手机本轮不在现场；本轮排版/动画验收使用隔离预览，不宣称新增了真机通信回归证据。Android 和配对协议没有改动。
- 在线服务是可降级来源，其匿名接口与歌词版本不能保证长期可用；不关闭证书校验、不依赖用户 Cookie。译文和罗马音只显示来源实际提供的数据。
- QRC 支持明文时间格式；不支持加密 QRC 容器。KRC 支持有界解码和解压。
- 截图主要验证当前 Windows 显示环境及 560×520、640×640、1120×760；真实多显示器不同 DPI 的移动仍需另行现场验证。
- 独立视觉 Agent 审查了实际截图，独立代码 Agent 审查了动画实现；静态截图不能单独证明连续动画流畅度，需结合运行采样和交互回归。
